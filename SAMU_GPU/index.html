SAMU 与 RG‑LRU：
结构差异如何转化为 GPU 性能

SAMU 用每个 token 的两个共享控制量 ct 和 dt，共同调节一组静态复数模态。本文把它与严格遵循 Griffin 方程和 RecurrentGemma 语义的 RG‑LRU 放在同一实现等级，逐项核对延迟、吞吐、特殊函数、内存流量、寄存器和并发占用。

结构差异

两种方法都有优化内核，差别在动态状态转移的计算方式。

两边的分块预填充都是 4 次 GPU 内核启动，单步解码都是 1 次。SAMU 仍需生成与状态同宽的写入向量，但只用两个 token 级控制量调节全部模态；RG‑LRU 则为每个通道生成输入门和递推门。

RG‑LRU Triton一次分块矩阵乘法
同时计算两组动态门→按官方方程计算输入门、递推门、衰减和归一化系数→分块长度 8/16/32；单步解码全部融合
SAMU Triton一次稠密矩阵乘法
同时计算写入向量和两个控制量→共享控制量 c,d 调节静态谱参数 ν,θ→分块长度 8/16/32；单步解码全部融合
参数与状态
16,772 对 16,768参数仅差 4；每个样本的 FP32 递推状态都是 512 字节
特殊函数
134 对 1,024分块长度 32 时，每个 token 静态统计的 exp/sigmoid 次数；RG‑LRU 另有 256 次平方根
内核启动
预填充 4 次；解码 1 次双方完全相同，排除启动次数造成的虚假优势
寄存器溢出
双方均为 0代表内核没有把寄存器临时值溢出到更慢的局部内存

由结构约束支持的优化 SAMU 的相位增量在当前参数化下有严格上界（±0.0772 弧度），因此可用带误差界的低阶多项式计算正弦和余弦，省去通用函数的角度归约。短序列还会在解析安全条件满足时使用有界指数近似；任何条件不满足都会回退到通用指数函数，方程本身不变。

serial、chunk 与 fused decode

这些 Triton 内核由本项目实现，但串行递推、仿射分块扫描和 kernel fusion 都是通用方法。贡献在于把它们严谨适配到官方 RG‑LRU，并构造同等级对手；不声称发明 scan 或 fusion。

可主张的结构贡献

共享谱坐标与可压缩块转移

每个 token 只显式生成 c,d 两个控制量，代替随 M 展开的动态 transition 描述；内核仍需为 M 个模态重建转移。解析界支持了已启用的特殊函数快速路径。块转移 P 还可由共享统计量重建，但 compressed-P 原型目前没有形成速度收益，只能列为后续工作。

    整模型规模分析

    按 Griffin 第 5 节的方法检查连续解码

    这部分把微型内核扩展到约 10.7 亿参数的共同解码器外壳。外壳、参数精度、词表、采样方式和状态字节数相同，只替换 SAMU 与 RG‑LRU 递推算子。

    延迟

    固定批量 B=16，从空前缀和 4096-token 前缀开始，连续生成 128、256、512、1024、2048 和 4096 个 token。前缀处理时间不计入解码延迟。

    B≤128 的完整轨迹吞吐

    先在 B=1–128 内搜索候选批量，再对前三个候选分别完整生成 512、1024、2048 和 4096 个 token。每个长度只在这些完整轨迹中选择最高吞吐；更大批量另列为短轨迹压力测试，不混入本结论。

    共同外壳

    宽度 2048、24 层、MLP 扩展倍数 3、词表 32,000。RG‑LRU 使用两个分块头，使两组门投影的参数量与 SAMU 的复数写入投影相同；这是一组参数匹配的方程实验，不冒充 RecurrentGemma 的整模型预设。随机权重只用于测系统执行，不用于比较语言模型质量。

    结论边界

    SAMU 与 RG‑LRU 都使用固定大小递推状态，因此都没有随前缀增长的 KV cache。这里检验的是递推实现差异，不复述论文中递推相对注意力的缓存优势。

    正在读取 H800 完整实验结果…

    t_{\mathrm{step}}\approx\frac{\text{参数字节数}+B\times\text{每个序列的状态字节数}}{\text{有效显存带宽}}
    这是 Griffin 公式 (5) 在两种递推模型之间的使用方式。两边状态大小相同，因此主要差别应来自参数读取是否充分复用、递推控制计算和 GPU 内核效率。

    范围说明这是随机权重的系统代理，不是训练好的 1B 语言模型，也不报告准确率或困惑度。它复刻论文的测量轴和规模，而不是复刻论文的 TPU 数字。
