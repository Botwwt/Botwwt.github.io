主结论使用同宽、近乎同参数、同 512 B FP32 state 的 Triton 对照。SAMU 在本次 L=128…65536 的全部 prefill 点领先 1.06×–2.03×；单 token decode 在 1.024 µs 事件分辨率下与 RG-LRU 持平。Mamba-3 仅放在“官方 best-native”轨道：同宽，但参数与 state 不匹配。

Architecture delta

不是“RG-LRU 没 kernel”，
而是动态 transition 的代价不同。

两边同为 4-launch chunk prefill 与 1-launch decode。SAMU 保留 state-sized write，但把动态 transition 从逐通道 gate 收缩成两个 token 级坐标；RG-LRU 完整保留两组 block-diagonal gates。

RG-LRU Triton1× packed block BMM→official iₜ, rₜ, aₜ, √γ→C8 / C16 / C32 / fused decode
SAMU Triton1× packed GEMM→shared c,d + static ν,θ→C8 / C16 / C32 / fused decode
Equal track
16,772 vs 16,768参数差 4；两边 state 都是 512 B / batch
SFU work · C32
134 vs 1,024每 token 的 exp/sigmoid 静态计数；RG-LRU 另有 256 sqrt
Launches
4 prefill · 1 decode双方相同；不再拿 Python loop 当架构优势
Profiler
zero spill双方代表 kernel；register 与 derived occupancy 逐 kernel 展示

SAMU-specific optimization 相位增量被结构性限制在 ±0.0772 rad，因此用有误差界的 degree-6/7 sin/cos 多项式替代通用范围归约；L≤128 还会在解析参数界通过时启用 bounded-exp，多项式不安全或实测无益时自动回退通用 exp。

    Equal Triton + official baselines

    cd benchmark
python run_equal_kernel_benchmarks.py \
  --output ../benchmark_results_equal_kernel \
  --rglru-source /path/to/recurrentgemma \
  --mamba-source /path/to/mamba

    计时使用 Triton driver CUDA events；每个样本前清 L2，保留全部 raw times。首次编译、参数打包、shape dispatch 和 setup 不进入样本。profiling 另见 profile_equal_kernels.py。

    Scope 新 kernel 是 inference-only；没有 backward 数字。Nsight Compute 不在镜像中，因此 measured DRAM bandwidth 与 SFU utilization 明确为 N/A；网页只展示逻辑字节下界、静态 SFU 操作数和编译器 metadata。
