PROPOSED GPU ARCHITECTURE

把 dense write 与
structured recurrence 分开优化

SAMU 最自然的 GPU 实现不是“普通串行 RNN kernel”，而是宽实数 GEMM、紧凑 coherent control、mode-parallel decode，以及面向 prefill / training 的压缩 affine scan。

核心判断 Tensor Core 负责规则的线性投影；scan / recurrence 负责时间依赖。

两者结构不同，也应分别建立 baseline。

01Implementation Audit / 实现审计

先确认现在的 SAMU，
再讨论未来的 kernel

结论来自当前仓库的 canonical JAX/Flax、PPO adapter、监督学习与 PyTorch formal-task scan。下表刻意分开“代码事实”和“用于 GPU 推导的等价记号”。

VERIFIED · CANONICAL

控制不是任意自由标量

\(\delta_t=M^{-1/2}\tanh(a_\phi)\,s_{\phi,t}\)
\(\eta_t=M^{-1/2}\tanh(a_r)\,\frac{s_{r,t}}{1+s_{r,t}^2}\)

其中 selector 是增广输入沿归一化方向的投影再过 tanh。本文用 d_t≡δ_t、c_t≡η_t 连接 GPU 记号。

VERIFIED · WRITE

JAX canonical write

\(\gamma_j=\sqrt{1-e^{-2\nu_j}}+10^{-8}\)

W_R、W_I 与 base ν 决定 write；token 控制只改 transition，不改本次 forward 内的 B。

IMPLEMENTATION DIFFERENCE

PyTorch formal wrapper 的 γ 已解耦

gamma_log 从 base radius 初始化，但随后是独立 parameter。它不再保证训练后始终等于 canonical 的 γ(ν)。GPU 报告以 JAX canonical 为主。

VERIFIED · INPUTS

PPO 的两条输入路径不同

write：shared_repr；selector：raw observation。监督/H64 路径通常让 raw task input 同时服务两支。

VERIFIED · WIDTH

M 是 complex modes

1 complex mode = 2 real scalars。项目里的 n_hidden / 某些 H 在本文记作 M；公平比较 state bytes 时必须匹配 D_state=2M。

NO CUSTOM-KERNEL RESULT

已有 generic scan，未有压缩 GPU scan

formal-task PyTorch 路径已有 work-efficient affine tree scan；但它物化每个 timestep × mode 的 multiplier，不是本文提出的 (C,G,D,q) custom kernel。No measured GPU kernel results found yet.

CANONICAL GPU NOTATION
\(A_{j,t}=e^{-\nu_j e^{c_t}}\,e^{i(\theta_j+d_t)}\)

随 token：ut, ct, dt, state

Complex notation → 实数 GPU 操作

x′= ρ ( cosφ·x − sinφ·y ) + write_R
y′= ρ ( sinφ·x + cosφ·y ) + write_I
ρ = exp(−ν·exp(c))φ = θ + d

不要 materialize complex At,j。kernel 直接生成 ρ、cosφ、sinφ，再更新 register 中的 x、y。

13Coherent Control · 为什么适合 GPU

token 只产生两坐标，
mode 提供丰富静态谱

低维动态控制不等于所有 modes 做相同更新：同一个 c,d 作用在不同 νj,θj 上，仍产生 mode-specific transition。

PER TOKEN / CTAg = exp(c)cos d, sin d
mode 0ν₀, θ₀ρ₀ · R(θ₀+d)
mode 1ν₁, θ₁ρ₁ · R(θ₁+d)
mode 2ν₂, θ₂ρ₂ · R(θ₂+d)
mode 3ν₃, θ₃ρ₃ · R(θ₃+d)
\(\cos(\theta_j+d_t)=\cos\theta_j\cos d_t-\sin\theta_j\sin d_t\)
\(\sin(\theta_j+d_t)=\sin\theta_j\cos d_t+\cos\theta_j\sin d_t\)

PROPOSED 每 mode 的 sinθ/cosθ 可预存；每 token 的 sind/cosd 可由一个 lane/warp/CTA 计算后广播。预计算还是重算必须 benchmark。

Conceptual pseudocode · serial mode recurrence
# Conceptual pseudocode — one lane owns one complex mode j
x, y = load_state(j)
cth, sth = cos_theta[j], sin_theta[j]
for t in timesteps:
    g = exp(c[t])
    rho = exp(-nu[j] * g)
    cp = cth * cos_d[t] - sth * sin_d[t]
    sp = sth * cos_d[t] + cth * sin_d[t]
    x, y = rho*(cp*x - sp*y) + wr[t,j], rho*(sp*x + cp*y) + wi[t,j]
store_state(j, x, y)
Conceptual pseudocode · phasor factorization
# Candidate factorization — benchmark against direct sincos(theta + d)
cos_phi = cos_theta[j] * cos_d[t] - sin_theta[j] * sin_d[t]
sin_phi = sin_theta[j] * cos_d[t] + cos_theta[j] * sin_d[t]
# cos_d / sin_d are token-wise and can be broadcast across the mode tile.
14–20Parallelism · Chunked affine scan

训练不能只并行 mode，
还要缩短 time 的并行深度

把每个 timestep 看成 affine operator，把连续时间段压成可结合的 summary，再对 chunks 做 prefix scan。

ONE STEP
\(T_t(z)=a_tz+w_t\)
→
TWO STEPS
\(T_1(T_0(z))=a_1a_0z+a_1w_0+w_1\)
→
ONE CHUNK
\(z_{out}=Pz_{in}+q\)
q 的直觉zero state→运行 chunk 内 recurrence→最终 state = qchunk

CURRENT FACT 当前 canonical Flax initialize_state 把 recurrent x,y 初始化为 zero；scan 推导仍保留 non-zero z0 的通用公式。

SAMU STRUCTURE
\(C=|S|,\quad G_S=\sum_{t\in S}e^{c_t},\quad D_S=\sum_{t\in S}d_t\)
\(P_{j,S}=e^{-\nu_jG_S}\,e^{i(C\theta_j+D_S)}\)
GENERIC DIAGONAL AFFINE(P, q)P ∈ ℂM, q ∈ ℂM
compress transition
SAMU(C, G, D, q)C,G,D = O(1); q ∈ ℂM

不要夸大：整个 summary 仍是 O(M)，因为 q 没有消失。真正压缩的是 dynamic transition P 的表示。

21–22Dual Backend · Decode 与 Prefill/Training

同一数学，两个执行问题

decode 只有一个新 token；prefill/training 已知整段序列。最优 parallelism 不同。

DECODElatency-first
  • time 不可并行：当前只有 1 token
  • mode-parallel：lane / warp 覆盖 modes
  • state cache 持久化，kernel 内放 register
  • control 只需两标量广播
目标：低 launch / state latency
PREFILL / TRAINthroughput-first
  • batch × time 先做 dense write GEMM
  • time × mode chunk jobs 并行
  • (C,G,D,q) 做 chunk prefix
  • 必要时 materialize 全序列 output
目标：短并行深度 + 高 occupancy
Pass 1每个 chunk 从 zero state 算 local q 与 C,G,D
→
Pass 2scan 得到真实 zin，重放或修正 chunk output
Conceptual pseudocode · decode kernel skeleton
# One token; mode-parallel. Not production CUDA.
parallel_for mode j:
    x, y = state_cache[j]
    rho, cos_phi, sin_phi = transition(control_t, nu[j], theta[j])
    x, y = rotate_decay_add(x, y, rho, cos_phi, sin_phi, write_t[j])
    state_cache[j] = (x, y)
Conceptual pseudocode · training chunk kernel skeleton
# Pass 1: batch × chunk × mode-tile jobs
summary[k] = local_zero_state_summary(write[k], control[k])
# Cross-chunk associative prefix
prefix = exclusive_scan(compose, summary)
# Pass 2: seed each chunk with prefix state and produce requested outputs
parallel_for chunk k: replay_or_correct(prefix[k], write[k], control[k])

每个版本只回答一个系统问题，并设置进入下一阶段的 evidence gate。

V1
BASELINE

V2

比较 per-lane / per-warp recompute、precompute 与 CTA-shared。

V3
PARALLEL TRAINING

Compressed affine scan

实现 (C,G,D,q)，先做正确且透明的 two-pass chunk scan。

V4
PROFILE-GATED

Advanced CuTe / CUDA

只有 profiling 证明值得时再做 single-pass、look-back、persistent 或 projection-recurrence fusion。

WHY NOT FUSE FIRST

GEMM epilogue 不能直接跨 row/time 解决 recurrence

真正 fusion 需要 persistent scheduling、producer/consumer pipeline 与自定义 CuTe/CUDA；它也可能降低 GEMM occupancy、Tensor Core utilization，并增加 register pressure。V1 的分离路径是测量 fusion 价值的必要基线。

不要夸大 · Research boundaries

01

SAMU 不是 O(L) total compute；write/state/q 仍有 O(LM) 或 O(M) 量。

02

(C,G,D) 是 O(1) transition metadata；完整 (C,G,D,q) 仍是 O(M)。

03

SAMU 不自动避开 memory-bound recurrence。

04

普通 decode kernel 之间 register state 不会自然持久化。

05

RG-LRU gates 可融合/重算；数学尺寸不能直接当 HBM bytes。

06

Mamba-3 已有成熟 hardware-aware training；chunking 本身不是 SAMU 的新发明。

07

precompute controls vs recompute controls 必须 benchmark。

08

没有公平 benchmark 前，不能声称 SAMU training 比 Mamba-3 快。

Conceptual pseudocode · chunk summary / composition / prefix
# Local zero-state summary for chunk S
C = len(S); G = sum(exp(c[t]) for t in S); D = sum(d[t] for t in S)
q = 0
for t in S: q = A(t) * q + write[t]
summary = (C, G, D, q)

# Later B after earlier A
def compose(B, A):
    P_B = reconstruct_transition(B.C, B.G, B.D, nu, theta)
    return (A.C+B.C, A.G+B.G, A.D+B.D, P_B*A.q+B.q)

# Conceptual exclusive scan — associative, order-preserving
prefix[k] = scan(compose, summary[0:k])
z_in[k] = apply(prefix[k], z0)
