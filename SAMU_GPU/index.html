SAMU 已形成 GPU Pareto 优势，
但优势有明确形状边界

我们把 RG-LRU 强化到当前最强合法 canonical backend，再让双方分别进行 shape dispatch。当前证据支持 SAMU 在主要短序列、宽中序列和长序列训练区域获得更低 mixer 延迟、更低 peak allocated 和更小前缀 scratch；它不支持“SAMU 在每个形状都更快”。

01 · 当前结论

优势来自低秩共享控制的执行结构

结论不是“SAMU 有一个更快的 scan”。真正被测量的是共享特殊函数、在线转移、复数仿射层级、共轭反向和低秩 controller-gradient reduction 共同形成的 shape-dependent backend。

延迟

主要 mixer 区域获胜

四个主要形状 F+B 快 24.6%、27.6%、37.3%、40.2%。到完整 recurrent block 后，公共层稀释收益，但仍快 5.8%–7.6%。

显存

peak allocated 与 scratch 更低

主要 mixer 形状 peak allocated 低 22.0%–23.5%；selected prefix scratch 约为 strengthened RG-LRU 的一半。

扩展

长序列与宽状态区域更清楚

D=1024 在 8K 仍输，32K 后转为明显优势；L=32K 时 D=1024–2560 的 F+B 优势为 37.3%–40.8%。

参数

动态控制不随状态宽度展开

同样真实状态容量下，SAMU 的 token-dependent 控制只有两个标量；RG-LRU 仍需两组 channel-wise dynamic gates。

03 · SAMU backend

数学不变，执行图重新设计

正式 controller 仍使用 normalized projection directions、zero-initialized signed amplitudes、规定的 H/mode scaling、q(r)=r/(1+r²)，且 amplitude=0 时精确退化到 RTU。

Et=exp(ct), Ct=cos(dt), St=sin(dt) λt,m=exp(−νmEt) · [(cosθmCt−sinθmSt) + i(sinθmCt+cosθmSt)] (λ₂,b₂)∘(λ₁,b₁)=(λ₂λ₁, λ₂b₁+b₂)
token-sharedct, dt→Et, Ct, St→register 中生成 λt,m
forwardchunk summary→group-local prefix→outer prefix→local correction + K32 replay
backwardconjugate reverse summary→grouped reverse prefix→K32 replay→[B,L,Ntiles,2] → [B,L,2]
01

shared-SFU

每个 token 只计算一次 E/C/S，再供全部 mode 使用，避免 mode-wise 重复特殊函数。

02

transition on the fly

在 register 中由 shared controls 与 static spectrum 生成 λ；不向 HBM 写出 lambda_r/lambda_i [B,L,M]。

03

fused write/output

写入归一化与输出 activation 融入 replay；最终选择 K=32，而不是把 RG-LRU 的 K=16 原样套用。

04

grouped complex-affine prefix

group-local、outer、local correction 三段只做 O(C) 次 summary composition。组合满足结合律但不交换，左右顺序保持原方程。

05

conjugate reverse

反向以共轭转移构造 reverse affine summary，再使用与前向对应的层级和 K=32 replay。

06

low-rank gradient reduction

tile 只输出两个 shared-control partial；deterministic FP32 第二阶段把 [B,L,N_tiles,2] 归约到 [B,L,2]。

CONTROLLER CACHE CONTRACT

保留精确导数所需的 p/r，而不从零 amplitude 反推

selected fp32_fused_coords path 在 forward 保存每 token 的 phase coordinate p 与 bounded-radial 链条所需的 raw r，连同原 recurrent input 交给 fused controller backward。direction normalization、direction-gradient projection 与 amplitude partial reduction 使用 FP32。E/C/S 足以重放 transition，但不足以独立恢复完整 controller derivative；实现没有用除以 signed amplitude 的方式重建 p/r。

EXACT CHUNK CLOSURE · OPTIONAL

compressed G/D 是合法的 memory path，不是默认 latency path

Gc=Σt∈c exp(ct)Dc=Σt∈c dtPc,m=exp(−νmGc) · exp[i(Kcθm+Dc)]

闭式使用 partial chunk 的真实 Kc，可用 G/D [B,C] 代替保存 P_r/P_i [B,C,M]，backward 再重建共轭 chunk transition。当前 compressed + grouped interaction 未通过最终 BF16 output gate，因此默认 dispatch 仍使用 materialized-P hierarchy。

05 · strengthened baseline

RG-LRU 没有被削弱

Google/Hugging Face RecurrentGemma 提供 canonical 数学与 correctness 语义；本项目的 Triton/CUDA 路径是面向 H800 的实现，不称作 Google 官方 CUDA 实现。

融合 preparation 与 recurrence

两张官方 block-diagonal gate projections 之后，sigmoid、transition、sqrt write factor、write 和 recurrence 在 custom operator 内处理，backward 重算 pointwise 项。

完整 canonical 语义

支持 arbitrary reset、chunk 内多次 reset、nonzero h₀ 与 grad h₀、partial final chunk、clipped sqrt backward、BF16 boundaries 与 FP32 carry。

精确 chunk hierarchy

K=8/16/32/64 候选都保留；最终选中 K=16 + grouped real-affine prefix32。forward/reverse 都保持非交换 affine composition 顺序。

同样允许 shape tuning

mode block 按形状校准：short b128，medium/D1024-long b256，D2048-long 与 400M-width b128。

公开实现：只在可比 contract 中排名

正在读取公开实现复现 JSON…

Fattori：直接运行固定 commit 的开源 hawk-pytorch，不称“官方实现”。其公开 kernel 不支持 canonical arbitrary reset、reset-token write normalization 与 nonzero initial state，所以只进入 secondary zero-state/no-reset comparison。

Hippogriff / Lingua：两者调用同一个 proger/accelerated-scan CUDA warp scan。完整 gate geometry 与 canonical RG-LRU 不同，因此只比较预先物化 affine coefficients 后的 pure scan。

允许的说法：在本次测过、同一受限 complete no-reset contract 的公开 RG-LRU 路径中，我们的实现延迟最低；pure scan-only 最快的是 accelerated-scan/Hippogriff，不是我们的 generic chunk32。

06 · correctness first

没有通过 gate 的候选不进入默认 dispatch

每个新路径依次通过 sequential FP32 mathematical reference、FP32/BF16 输出与全部相关梯度、kernel benchmark、完整 recurrent block。阈值没有在看到结果后放宽。

GATE 1数学等价T=1/2/3/7/31/32/33、partial chunk、h₀、reset、packed boundary
GATE 2数值正确output、input/write/h₀、ν、θ、shared retention/phase gradients
GATE 3kernel 证据F、B、F+B、memory、scratch、launches、两轮样本
GATE 4block 证据公共 projection/conv/norm/MLP 加回后仍需获益
PASS · 32K

full grouped K32

宽状态 32K gate 通过，因此 grouped complex-affine forward/reverse 可在该区域默认启用。

REJECT · 65K/131K

full grouped forward

BF16 output relative L2 为 5.84e-6 / 7.49e-6，超过预声明 5e-6；早期约 43% latency win 不进入最终结论。

PASS · 65K/131K

hybrid very-long path

D=1024 输出与 serial K32 bitwise identical；input-grad relative L2 为 4.72e-6 / 7.09e-6；最大 parameter-grad relative error 为 3.29e-5 / 1.67e-4。

DISABLED

compressed G/D default

闭式与 memory 表示正确，但 compressed + grouped K32 的 BF16 output relative L2 6.38e-6 超过 5e-6，而且 hierarchy 需要额外重建 P，因此不是默认 latency path。

其余未选候选

  • FP32 atomic shared reduction：数值接近，但非 bitwise deterministic，且没有快过 deterministic two-stage。
  • two-stage spectral reduction：D1024 中性，D2048 约慢 0.7%，还增加 scratch。
  • static spectral cache：medium/D2048 中性，long D1024 约慢 1.7%。
  • BF16 controller projection/accumulation：direction gradient relative error 约 2e-3；默认保留 FP32 fused-coordinates controller path。
  • K=64 complex replay：Triton 编译反复被终止，没有合法 runtime 结果，继续使用 K=32。

07 · 最终可写结论

当前证据精确支持什么

下面文字是本页唯一推荐的结论口径。它把测量对象、硬件、优势区域和未覆盖范围同时写清楚。

在单张 NVIDIA H800 PCIe 80 GB、BF16 输入/输出与 FP32 recurrent carry 下，SAMU 的 low-rank coherent control 可以转化为 shape-dependent GPU Pareto advantage。相对于同样获得融合 preparation、精确 chunk forward/backward、线性工作量 affine hierarchy 和 shape dispatch 的 strengthened canonical RG-LRU，SAMU 在四个主要 complete-mixer 训练形状上将 F+B 延迟降低 24.6%–40.2%，将 peak allocated 降低 22.0%–23.5%；在单个完整 recurrent block 上将 F+B 延迟降低 5.8%–7.6%，在该 block 的 AdamW step 上降低 3.8%–6.5%。优势来自 shared token special-function reuse、mode-wise transition on-the-fly generation、complex-affine hierarchy、conjugate reverse scan、较小 prefix scratch 和 low-rank controller-gradient intermediates。该优势不是全形状成立：B=1、L=8192、D=1024 时 SAMU 仍慢 12.4%；当前结果也不证明 SAMU 的 pure scan primitive 最快，不证明 strengthened-baseline 下的多层完整语言模型或推理解码已经获胜，也不提供收敛、任务质量或多 GPU 结论。

可以写

  • shape-dependent GPU Pareto advantage
  • 主要 mixer、单 block 与 one-block optimizer step 的绝对时间和百分比
  • 更低 peak allocated、prefix scratch 与 mixer 参数量
  • 长序列/宽状态区域以及明确 crossover

不能写

  • “SAMU 在所有形状都比 RG-LRU 快”
  • “SAMU 拥有最快 pure scan”
  • “当前已证明 400M/1.3B 完整模型 optimizer step 更快”
  • “65K/131K 仍有约 43% 优势”
  • “compressed G/D 普遍降低 latency”
